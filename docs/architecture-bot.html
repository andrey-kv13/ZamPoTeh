1. Назначение продукта

ЗамПоТех — персональный помощник владельца авто в Telegram (в перспективе тот же backend для APK). Пользователь описывает запчасть своими словами; бот привязывает запрос к конкретному автомобилю в гараже, уточняет сторону / двигатель / PR-коды при необходимости и возвращает справку из открытых источников, не подставляя каталожные номера «из головы».

Ключевые модули UX

  • Гараж — до 10 авто по VIN, карточка с открытым decode + поля из СТС (двигатель, пробег, PR).
  • Поиск запчасти — NL-запрос, FSM-уточнения, PDF/стеллаж, ссылки на агрегаторы (Exist, Emex, …).
  • История по VIN — общая для всех владельцев этого VIN (без имени/пробега); можно скрыть свой запрос.
  • Стеллаж — учёт купленных/установленных деталей (формулировка пользователя, не OEM).
  • Напоминания — по пробегу/дате; фоновая задача каждые 5 минут.
  • Профиль — город, режим интервалов, удаление аккаунта.
  • Админка — статистика, блокировка, суточный лимит (для будущего платного адаптера).

6. Middleware и доступ

  • Только личные чаты (ChatType.PRIVATE).
  • Без согласия (оферта + ПДн) доступны только /start, /help, consent:*.
  • На каждый update: создаётся async SQLAlchemy session → handler → commit.
  • user.is_blocked — блокировка (кроме админов).

10. Разбор VIN

lookup_vin(vin, year) — параллельно NHTSA, mcp.vin, DB.VIN; затем interpret():

  • WMI из CSV + vininfo
  • Коды VAG (знаки 7–8), BMW type (4–7), Avtotor BMW (11-й знак = model year code, не всегда год выпуска)
  • Контрольная цифра ISO 3779
  • explain() — HTML для Telegram; build_vin_source_lines() — блок источников

Карточка в гараже: show_car → повторный lookup_vin + car_spec_rows().

Не выдумывать OEM. Если открытый источник не дал модель/номер — показывать формулировки из texts.py (NO_CATALOG_NUMBER, EMPTY_RESULT).

11. Поток поиска запчасти

  1. start_search — активное авто из гаража (ownership=current).
  2. parse_query — intent (oil, brake, mount, stabilizer_*, part), side, артикулы из текста.
  3. FSM уточняет: сторона (paired), код двигателя (oil/mount), КПП (mount), PR (стабилизатор).
  4. search_open_parts(brand, model, year, text, intent) → OpenReport.
  5. result_messages: блок «Можно включать в заказ» = всегда NO_CATALOG_NUMBER; открытые hits отдельно; при oil/brake — maintenance.py.
  6. Кнопки: повтор, скрыть из истории VIN, стеллаж, PDF, URL на агрегаторы (marketplace_links.py).

Адаптер каталога не подключён: Search.counted для лимита почти не растёт; статус open_checked.

13. Продуктовые правила (обязательны при доработке)

  • Не генерировать и не угадывать OEM, цены, аналоги без лицензированного источника.
  • Артикулы из текста пользователя помечать как «каталогом не подтверждены».
  • Disclaimer в каждом результате поиска (DISCLAIMER).
  • История VIN — прозрачность: чужие личные данные не показывать; скрытие запроса — только для автора.
  • Голос не распознаётся; фото сохраняется без OCR.
  • Регион MVP: РФ; язык UI — русский.

14. Очередь 2 (ожидаемая интеграция)

Место для платного адаптера (отдельный модуль, feature flag):

  • Laximo.CAT / TecDoc Web Service — OEM по VIN, кроссы.
  • Тогда: отдельный блок «Подтверждено каталогом», лимит search_daily_limit, Search.counted=True.
  • Не смешивать номера каталога с открытыми hits без явной пометки источника.

15. Тесты и качество

cd app
.\.venv\Scripts\python.exe -m unittest discover -s tests -v

Покрытие: парсинг VIN, BMW Avtotor, open_sources, запрет «выдуманных» номеров в результате, delete car/account, admins из settings.

Что проверить после изменений

  • Добавление авто по VIN (US, EU, Avtotor BMW).
  • Поиск «тормозные диски», «замена масла» — комплект + моменты, без OEM.
  • Один poller на токен.
  • Новый админ — id в ADMIN_IDS + restart + /start у бота.
